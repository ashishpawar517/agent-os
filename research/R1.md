# Provider Landscape: OpenRouter & NVIDIA NIM Function Calling

## OpenRouter
- OpenRouter provides a unified API that is compatible with the OpenAI Chat Completions API.
- It supports function/tool calling via the `tools` parameter in the request body.
- The `tools` property is an array of objects, each describing a function the model can call.
- Each tool must have a `type` of `"function"` and a `function` object with `name` and `description`.
- Optional `parameters` (JSON Schema) define the function's inputs.
- The model can be instructed to use tools via the `tool_choice` parameter (`"auto"`, `"none"`, or specific `{"type": "function", "function": {"name": "..."}}`).
- Parallel tool calls are enabled via `parallel_tool_calls: true`.
- Source: OpenAPI spec inspected from `https://openrouter.ai/openapi.json` (see `ChatRequest` schema, `tools` and `parallel_tool_calls` fields).

## NVIDIA NIM
- NVIDIA NIM (NVIDIA Inference Microservices) provides containerized, self-hosted LLMs with an OpenAI-compatible API endpoint.
- As it exposes the same OpenAI API contract, it supports the `tools` parameter for function calling in the same way as described above.
- The NIM documentation confirms compatibility with the OpenAI Chat Completions API, including function calling.
- Source: NVIDIA NIM documentation (e.g., https://docs.nvidia.com/nim/latest/) and typical NIM deployment guides.

## Implications for Uniform Provider Abstraction
A uniform provider abstraction for agent-os should:
1. Accept a `tools` array (as per OpenAI schema) in the request to the provider.
2. Honor `tool_choice` and `parallel_tool_calls` flags.
3. Stream responses if needed (both providers support streaming).
4. Authenticate via API key in the `Authorization: Bearer <token>` header.
5. Route requests to the appropriate endpoint (OpenRouter: `https://openrouter.ai/api/v1/chat/completions`; NIM: `http://<host>:<port>/v1/chat/completions`).
6. Handle the function call responses from the model and execute the corresponding tool (agent component) before returning results.

Thus, both providers can be treated identically at the API contract level for function‑calling capable models.
